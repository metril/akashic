# Configuration reference

Every Akashic environment variable, with its default and what it
controls. The API reads these at startup from the process
environment — in compose deployments, that means the `.env` file
referenced by `api.env_file` in [compose.yaml](../compose.yaml).

The authoritative source for defaults is
[`api/akashic/config.py`](../api/akashic/config.py); this page is
generated by hand and should be refreshed alongside any change to
that file.

## Database & infrastructure

| Var | Default | What |
|-----|---------|------|
| `DATABASE_URL` | `postgresql+asyncpg://akashic:changeme@localhost:5432/akashic` | Postgres DSN. Must use the asyncpg dialect. |
| `MEILI_URL` | `http://localhost:7700` | Meilisearch base URL. |
| `MEILI_KEY` | `changeme-meili-key` | Meilisearch master key. |
| `REDIS_URL` | `redis://localhost:6379/0` | Redis pubsub + dirty-set storage. |
| `TIKA_URL` | `http://localhost:9998` | Apache Tika endpoint for content extraction. |

## Sessions & tokens

| Var | Default | What |
|-----|---------|------|
| `SECRET_KEY` | `changeme-secret-key` | JWT signing key. **Override in production.** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `60` | Access-token TTL. |
| `REFRESH_TOKEN_EXPIRE_DAYS` | `30` | Refresh-token TTL. Matches typical SSO session lifetimes. |

## Authentication

See [authentication.md](authentication.md) for setup walk-throughs.

### OIDC

| Var | Default | What |
|-----|---------|------|
| `OIDC_ENABLED` | `false` | Master toggle for OIDC login. |
| `OIDC_DISCOVERY_URL` | (empty) | Your IdP's `.well-known/openid-configuration` URL. |
| `OIDC_CLIENT_ID` | (empty) | OIDC client ID issued by your IdP. |
| `OIDC_CLIENT_SECRET` | (empty) | OIDC client secret. |
| `OIDC_REDIRECT_URI` | `http://localhost:8000/api/auth/oidc/callback` | Where the IdP returns to after auth. |
| `OIDC_STRATEGY` | `auto` | Identity resolution: `auto` \| `claim` \| `ldap_fallback` \| `name_match`. |
| `OIDC_USERNAME_CLAIM` | `preferred_username` | Claim used as username. |
| `OIDC_EMAIL_CLAIM` | `email` | Claim used as email. |
| `OIDC_SID_CLAIM` | `onprem_sid` | Claim carrying AD `objectSid`. |
| `OIDC_UID_CLAIM` | `uidNumber` | Claim carrying POSIX UID (SSH/NFS sources). |
| `OIDC_GROUPS_CLAIM` | `groups` | Claim carrying group memberships. |
| `OIDC_GROUPS_FORMAT` | `sid` | How groups are encoded: `sid` \| `name` \| `dn`. |
| `OIDC_DN_CLAIM` | `ldap_dn` | Claim carrying user's full LDAP DN (used by `ldap_fallback`). |

### LDAP

The `LDAP_*` variables are shared by **two** code paths: direct
LDAP login (when `LDAP_ENABLED=true`) and the OIDC `ldap_fallback`
strategy. See [authentication.md](authentication.md) for the
distinction.

| Var | Default | What |
|-----|---------|------|
| `LDAP_ENABLED` | `false` | Master toggle for direct LDAP username/password login. |
| `LDAP_SERVER` | (empty) | LDAP server URI, e.g. `ldaps://ad.example.com:636`. |
| `LDAP_BIND_DN` | (empty) | Service account DN for the user-search step. |
| `LDAP_BIND_PASSWORD` | (empty) | Service account password. |
| `LDAP_USER_BASE` | (empty) | DN under which to search for users. |
| `LDAP_USER_FILTER` | `(uid={username})` | Search filter template. `{username}` is escaped + replaced at runtime. |

## Permissions & caching

| Var | Default | What |
|-----|---------|------|
| `GROUP_CACHE_TTL_HOURS` | `24` | TTL for the per-user group → file-visibility cache. |
| `BROWSE_ENFORCE_PERMS` | `false` | When `true`, Browse and entry-by-id apply the same per-user ACL filter Search has always applied. Off by default so existing deployments don't suddenly hide files on upgrade. |

## Audit

| Var | Default | What |
|-----|---------|------|
| `AUDIT_RETENTION_DAYS` | `0` | `0` = keep events forever. Set to N to enable a daily prune of events older than N days. See [admin.md](admin.md). |

## Performance

| Var | Default | What |
|-----|---------|------|
| `STREAMING_TOPCHILDREN` | `false` | When `true`, ingest batches mark touched parent paths in a Redis dirty set; a background worker incrementally rebuilds the storage explorer's `top_children` rollup so the Storage view updates mid-scan instead of waiting for post-scan rollup. Off by default — recommended on for installs > ~1M files. |
| `SLOW_QUERY_MS` | `100` | Global threshold for the slow-query log. Any SQL statement that exceeds this duration is logged at WARN with a truncated SQL preview. Lower it to surface borderline regressions earlier; raise it on noisy installs. |
| `SLOW_QUERY_MS_OVERRIDES` | `{}` | Per-endpoint overrides as JSON. Keys are substrings matched against the request path; first match wins. Example: `SLOW_QUERY_MS_OVERRIDES='{"browse": 50, "ingest": 200}'` tightens Browse/Search but relaxes the (intentionally heavier) ingest path. |

## Scanner / discovery

| Var | Default | What |
|-----|---------|------|
| `STALE_SCAN_THRESHOLD_MINUTES` | `60` | Watchdog window — pending or running scans older than this are marked failed and the source is freed for re-scan. |
| `SCANNER_DISCOVERY_ENABLED` | (unset) | First-boot seed for the runtime `discovery_enabled` server setting. Once the setting row exists, runtime PATCHes from the UI take precedence. Set in IaC if you want discovery on by default. |

## Feature-flag tips

- **`BROWSE_ENFORCE_PERMS`** is expected to become the default in
  a future release. Test with it on before flipping in production
  — make sure your users have FsBindings, and (ideally) that the
  Phase 4 backfill has run on existing entries.
- **`STREAMING_TOPCHILDREN`** adds a small ingest overhead (a
  Redis SADD per touched parent batch) in exchange for live
  Storage updates. Recommended on for any deployment large enough
  that a post-scan rollup feels stale.
